# How the runtime works

This is the reference for `skills/poteto-mode/hooks/pstack-hook.mjs` and the rules it runs. The [README](../README.md) has the short version.

## What each hook event does

One hook script, `pstack-hook.mjs`, answers eight events:

- `SessionStart` and `SubagentStart` inject the skills directory, the transcript directory, the tool mapping, the standing skips and the model table. A `poteto-agent` or `pstack-reader` subagent also gets the mode reminder.
- `UserPromptSubmit` injects the mode reminder while the session is in poteto mode, except on a task notification. The mode starts at the `/poteto-mode` prompt itself and ends at `/poteto-mode off`. When the entering prompt reads as work the user reviews after stepping away, its reminder also asks to route it through figure-it-out. The reminder ends with six lines headed "Rules most often missed": keep each task item's state current, write a skipped step's `skip: <reason>` on its item, read `prove-it-works.md` by its full path for a fix or a verification, label each claim, paste a bug fix's failing and passing output, and use no long dash or mid-sentence colon connector.
- `PreToolUse` on `Bash`, `PowerShell`, the edit tools, the task tools, MCP tools and `Agent` asks `asks.mjs` what the pending call owes. The hook reads only what the call's input says for certain: an edit tool's path, a task tool's items, a spawn's brief, an MCP tool name, or a commit, PR-open or PR-merge verb from one fixed table in `hooks/kinds.mjs`. , a glob or a quote names nothing, and a heredoc body is text, so a Python or Node script that writes a file stays unseen. The hook never guesses what a shell command reads or tests. In a poteto-mode session a rule raises an ask when a doc it names is unread, or when it names no doc. A shell command reads a doc only through a statement whose command is a file reader (`cat`, `head`, `tail`, `less`, `more`, `sed -n`, `awk`, `type`, `bat` or `Get-Content`): the reader names the doc's path, names a principle's slug inside the principles directory, globs that directory, or names `SKILL.md` after a `cd` into the skill's directory. A deny carries one ask, the first the call owes in the order of the `RULES` table: route, ledger, delegate, design, design-read, then the rest. The retry raises the next, so a call that owes N asks takes N retries, plus a hard ask's re-denies. Each ask ends with its own `[pstack:<key>:<hash>]` tag, where the hash is 8 hex digits of the ask's target. The hook reads those tags back from the transcript.

	An ask is one-shot. Once its tag is in the transcript, the retry and every later call with the same tag go through for the rest of the mode span, and nothing checks whether the worker complied. A worker that decides an ask does not apply writes `skip <name>: <reason>` for the user and retries. The asks, keyed by the rule that raises them:
	- `route` asks the main session once per mode span, at its first change, when nothing in the span read a playbook or the figure-it-out skill. A change is an edit of a code file, a skill doc or a reader doc, a commit, or a `poteto-agent` spawn whose brief names no playbook. An edit of scratch, generated, config or data files is not a change, and neither is a shell command that only reads or another agent type's spawn. A brief names a playbook on a `Playbook:` line, by a catalog playbook's `playbooks/<name>.md` path, or as "<title> playbook" in prose. A playbook read in an earlier call of the same assistant message counts as routed. A read placed after the change in that message costs one ask, because its record can reach the transcript after the change's result. A subagent is never asked, since its parent owns routing. The ask names `skip route: <reason>` as the way to decline, and on a code edit it goes before the Shape line.
	- `ledger` asks the main session, at its first call after a playbook read with no task list opened since, for one TaskCreate per step.
	- `task-merged` asks for one item per step when a new task subject spans a step range such as `1-8` of a live playbook.
	- `step-done` asks the main session to read a step's skill before a TaskUpdate or TodoWrite marks that step completed. It leaves out a skill the step names under a condition, which the worker judges, and one the step hands to another actor. A `skip` naming the skill, a `skip: <reason>`, or a done word beside a prior session, in the item or the completing call answers it. Sentences the item copies from the step's own line do not count, since they are the playbook's words.
	- `design` asks the main session, at its first edit of a code file in each turn, for a line that starts `**Shape.**`, written in the reply before it retries the edit unchanged. A visible text earlier in the same turn that already holds a `**Shape.**` line with content answers it, so an edit the delegate ask held back is not asked again for the line. A `skip design: <reason>` line in the turn answers both `design` and `design-read` for that turn. `design-read` asks at the next code edit after that deny for a read of `principles/model-the-domain.md`, once per mode span. Each deny asks for one thing, because a deny that asked for both got the read and lost the line. The `design-read` deny also says to read architect when the change crosses a function boundary. Before any of these, `delegate` asks the main session at its first code edit inside a repository (a `.git`, `.hg`, `.jj`, `.sl` or `.svn` directory above the file, no higher than a UNC share root) under a playbook with a delegation step, once per playbook, when no subagent was spawned since that playbook was read: spawn `poteto-agent` on the playbook's role model, or write `skip delegate: <reason>`, which Feature's wording leaves out. An edit to a test or harness file owes no delegate ask. `isHarness` in `hooks/kinds.mjs` names these files by name: `*.test.*`, `*.spec.*`, `*_test.*`, `*_spec.*`, `test_*`, `conftest.py` or a bench file. It also names them by directory: `test/`, `tests/`, `__tests__/`, `spec/`, `testdata/`, `fixtures/`, `bench/`, a `src/*Test/` such as `src/androidTest/`, or a `*.Tests/` project. The same predicate keeps a doc in those places from counting as a skill doc or a reader doc. After each `poteto-agent` spawn, the parent's first code edit in the repository is asked once to send the change back to the delegate. An explorer, reader or reviewer spawn opens no new ask. A path under the temp directory, under a directory named `scratch`, `.scratch` or `scratchpad`, or under a `tmp` directory that is not directly inside a source directory such as `src/`, is scratch and raises nothing, and so is a path under a generated directory such as `dist/` or `node_modules/`. A code file git ignores, such as a profiling script under a gitignored `.verify/`, is the worker's own scratch and raises no code-edit or change ask. The hook asks `git check-ignore` from the file's nearest directory, once per file and hook process, and reads a timeout after 1.5 s or any error as not ignored. A path is code unless `hooks/kinds.mjs` names it a doc, config, data, lock or asset file, so a language no list names still counts.
	- `skill-edit` asks for the authoring-a-skill playbook and the unslop skill before an edit of any markdown file inside a skill's directory, or an agent under `.claude/agents/` or a plugin's `agents/`, outside test fixtures. It asks once per skill directory, or once per agent definition, so a command that writes several files of one skill owes one ask.
	- `docs-prose` asks for technical-writing and unslop before an edit of a README, CONTRIBUTING, ARCHITECTURE, CLAUDE or AGENTS document, or a document under `docs/`.
	- `decision-log` asks for the show-me-your-work skill before an edit of, or a shell `>>` append to, a decision log such as `decisions.tsv`, or a run of its `log.sh`: a statement whose tool is `log.sh`, or whose first `bash` or `sh` operand is, with a variable the command sets to a literal read as its value. A command that only names `log.sh`, such as a `grep` or `cat` of it, is not a run. A `decisions.md` counts only under `.audit/`, since elsewhere it is usually a design record.
	- `deslop` asks once per commit that follows a code edit or a `poteto-agent` spawn since the previous commit, to read the deslop skill if it is unread and run it on the staged diff. A skill read for an earlier commit does not answer a later one. A commit with no new code edit is not asked, and neither is a commit into a throwaway repository: one the same command made with `git init` or `git clone` under a temp or scratch directory, or one an earlier command made there with `git init` or by cloning such a repository, as `git init --bare` then `git clone` sets up a fixture. A clone of a real remote into a scratch directory is real work, and its commits are still asked. The deny also asks to drive a UI, CLI or IDE change with its control skill, and under Hillclimb to commit only a kept attempt.
	- `review` and `pr-prose` ask for no-comments, or a `comment-sicko` spawn, and for technical-writing and unslop before a PR opens.
	- `shipping` asks for the Shipping playbook before a PR merge.
	- `spawn-cites` asks the spawner to read a principle its brief cites.

	Three asks are hard, because their answer is literal in the next call, and deny again while the call still does what they refuse, 3 times in all per tag: `task-merged`, `model-role` for a delegate off its playbook role's model in the model table, and `pr-draft` for a PR opened as a draft. With nothing owed, a spawn whose brief has a `Playbook: <title>` line gets that playbook's steps appended, with no permission decision, so the user's own rules still decide whether it runs. A `poteto-agent` call whose payload names no agent id goes through, because the hook cannot find the transcript that holds its tags. A tag counts from any errored tool result.

	A standing skip waives an ask in every mode span. Put `skip <name>: <reason>` lines in `~/.claude/pstack-skips.md`. For example, `skip technical-writing: the project's CONTRIBUTING.md sets the doc style` counts technical-writing as read for every ask. A standing skip may name only `technical-writing`, `unslop`, `docs-prose`, `pr-prose` or `pr-draft`. The hook ignores a line that names anything else, and counts an honored line by its name alone.

	A project's `.claude/pstack-skips.md` counts only when `~/.claude/pstack-skips.md` holds `trust <project root> <sha256 of the file>` for its current contents, so a file that arrives with a clone or a pull waives nothing. `SessionStart` shows the user every active, ignored and untrusted standing skip in a `systemMessage`, with the trust line to add for an untrusted file, and the session context shows the model the same list. A missing or unreadable file changes nothing. `PreToolUse` refuses every agent's edit of a file named `pstack-skips.md`, and every shell command that names one and writes, in the mode or out of it, because an agent that writes its own standing skip excuses itself.
- `PreToolUse` on `Bash` denies a `pstack-reader` subagent any shell command that writes.
- `PostToolUse` on `Read` and on `Bash` hands back a playbook's numbered steps with their indented sub-items, verbatim, when an agent in the mode reads that playbook from the installed tree with the Read tool or with a shell command that names its path. After a commit that leaves every task item in its first state, the `Bash` hook adds a note to update the items, once per mode span.
- `SessionEnd` removes the session's mode marker.
- `Stop` and `SubagentStop` block an in-mode stop on a finding the gate can see for certain: the reply cites a principle whose file was never read, any visible text of the turn or its reply uses the long dash (the finding quotes the first line that does, asks for a rewrite when the reply holds it, and otherwise asks only not to use it again, since sent text cannot change), the turn edited code and no visible text or reply of it holds a `**Shape.**` line with content or a `skip design: <reason>` line, the session worked without reading the unslop skill, edited files or committed without reading any principle, or opened task items and never updated one, or a trail playbook (Autonomous run, Orchestrate, Hillclimb, Multi-phase plan) is live and nothing wrote a decision trail. A shell append to a decision log, a `log.sh` run, or a `skip show-me-your-work:` line in the reply answers the trail finding. Each finding carries a tag and blocks once per mode span. A stop the hook re-entered, with `stop_hook_active` set, passes on every tag its previous stop would have blocked, and passes outright when its turn has no previous stop, so a block whose feedback never reached the transcript cannot repeat. In a `claude -p` session, the gate also blocks a stop while the Stop payload's background tasks hold a shell and nothing that keeps the session open, because ending the turn stops that shell. That finding blocks up to 3 times per task. The reason ends by asking for the complete final answer again. The gate logs, and never blocks, each doc-read ask whose call went through with the doc still unread, to `~/.claude/pstack/retry-unmet.log`. `PSTACK_GATE=observe` only logs what it would block to `~/.claude/pstack/gate-observe.log`, and `PSTACK_GATE=off` turns the gate off.

The `PreToolUse` registration for the file and task tools and the `PostToolUse` registration for `Bash` source `hooks/in-mode.sh` before Node starts. It reads the payload with the shell's `read` builtin and ends the hook unless `~/.claude/pstack/live/<session_id>` exists or the payload names `poteto-agent`, `pstack-reader` or a playbook path. The hook derives the mode from the transcript on every event it sees and writes or removes that marker to match. A stale marker costs one Node start and never changes a verdict.

`CLAUDE_CODE_ENABLE_TODO_TOOLS=1` turns on the task tools (`TaskCreate`, `TaskUpdate`) that the skills open their step lists with. `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS=0` lets `claude -p` wait on a background agent for as long as it runs, where the default kills the run after 600 s. A hook that fails exits cleanly and appends one line to `~/.claude/pstack/hook-errors.log`.

The hook path goes through the `poteto-mode` link, so the settings entry stays the same wherever the clone lives. The command changes into the hook's directory before it starts Node. Git Bash turns `~` into `/c/Users/...`, and in a session started with `MSYS_NO_PATHCONV=1`, Node reads that path as `C:\c\Users\...` and the hook fails without telling the session.

## How the skills load

Most skills set `disable-model-invocation`, so the Skill tool refuses them and their descriptions stay out of every session. When one skill names another, the hook tells the agent to read that skill's `SKILL.md` by path. A name such as `principle-prove-it-works` resolves to `skills/poteto-mode/principles/prove-it-works.md`. Keep the flag when you add a skill. Seven skills leave it off and trigger on their descriptions: the four `cursor-team-kit` skills (`control-cli`, `control-ui`, `deslop` and `verify-this`), `setup-pstack`, `verify-pstack` and `typescript-best-practices`. To list them, run `grep -L '^disable-model-invocation: true' skills/*/SKILL.md`.
